# 第 04 讲 工具注册与定义

看懂普通 Python 函数如何变成模型可选的工具。

## 注册工具时，模型拿到的是一份契约

假设你定义 `echo(text: str)`。如果把整个函数实现发给模型，它既没有 Python 执行环境，也不需要知道实现细节。MiniBot 交给模型的描述只回答三个问题：这个工具叫什么、适合什么时候用、参数是什么形状。Python 函数保留在本地，等模型按名称请求调用时再执行。

注册发生在 `Minibot.register_tool()`。普通 callable 被包装成 `FunctionTool`，名称和描述默认来自函数名称和 docstring，参数结构由 `schema_from_callable()` 读取签名及类型注解并生成。想指定其他名称、描述或参数 Schema 时，可传入带 `func` 的 `ToolSpec`。观察有默认值的参数，你会看到调用契约和 Python 签名需要配合，而执行时还会再次校验参数。

## 定义如何从注册表变成请求字典

| 层次 | 负责的事 |
| --- | --- |
| `ToolRegistry` | 以名称保存工具对象，供定义收集与执行查找共用 |
| `BaseTool.get_definition()` | 用对象的 `name`、`description`、`input_schema` 创建 `ToolDefinition` |
| `ToolDefinition.to_dict()` | 生成带 `type="function"` 和嵌套 `function.parameters` 的请求格式 |
| Agent 与模型客户端 | 每次请求时读取当前工具定义，并随消息发送 |

现在重新打开 `get_definitions()`。你会看到它遍历工具并调用 `tool.to_dict()`。要找字段在哪里设置，应沿具体工具类型进入构造器或属性。内置工具可以直接以类属性声明名称和描述，通过 `input_schema` 返回固定结构。自定义函数把这一步交给包装器，最后汇合到同一序列化路径。

**思考与答案**　工具注册成功后，为什么问「你好」可能一次都没调用它？注册只增加模型可用的能力。模型依据任务与工具描述选择是否生成工具请求，执行由下一章的分发链完成。

## 配置核对

tools.enabled、tools.disabled 参与内置工具注册。SDK 的 ToolSpec 可提供名称、描述和 Schema。受限 Docker 工作区拒绝自定义 Python 工具。

## 使用与验证

定义一个只返回文本的 echo(text: str) 函数，通过 Minibot(tools=[echo]) 注册，打印注册表中名为 echo 的定义，检查描述与必填参数。

```python
from minibot import Minibot


def echo(text: str) -> str:
    """原样返回输入文本。"""
    return text


bot = Minibot(tools=[echo])
for definition in bot.agent.tool_registry.get_definitions():
    if definition["function"]["name"] == "echo":
        print(definition["function"])
```

检查输出的 `description`、`parameters.properties.text.type` 和 `parameters.required`。构造并检查这个定义无需调用模型。
