# 模型请求的上下文限制

MiniBot 在发送每个模型请求前都检查其大小，根据系统提示词、消息和工具定义估算输入。流式、非流式请求和内置 `Task` 子 Agent 均使用同样的检查。

## 配置限制

以下是默认设置。在 MiniBot 应用主目录下全局 `config/default.yaml` 的 `llm` 部分设置这些键。SDK 用户可将 `LLMConfig(max_context_tokens=..., max_tool_output_chars=..., max_tokens=...)` 传给 `Config(llm=...)`。

```yaml
llm:
  max_context_tokens: 100000
  max_tool_output_chars: 16000
  max_tokens: 8000
```

`max_context_tokens` 是模型输入和输出的总窗口。`max_tokens` 是主 Agent 和内置 `Task` 子 Agent 首选的生成上限。token 数是估算值，服务商对同一请求的计数可能不同。

## MiniBot 如何调整请求

`max_tool_output_chars` 限制模型请求中每条工具结果的长度，最小值为 32 个字符。默认将大结果保存为[会话产物](上下文卸载.md)，在工具结果中附上引用和预览。对于旧历史或禁用卸载后的超长工具结果，请求构建器会截断文本并附加截断标记。已保存的历史保持原样。

MiniBot 为输出预留空间，受配置的生成上限和剩余[运行输出预算](运行预算.md)约束。空间不足时，从请求中移除较早轮次，保留最新轮次及其中的用户确认回复、工具请求和结果，也保留显式的系统和开发者消息。较早的摘要也可能被移除。磁盘上的会话仍包含这些消息。

保留的输入无法留出首选输出空间时，MiniBot 会降低生成上限。如果完全没有输出空间，会在调用服务商前报告 `context_window_exceeded`。可选的压缩请求仅在待摘要历史能放入请求时运行。
