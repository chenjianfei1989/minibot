# 文件检查点

文件检查点可查看和撤销 MiniBot 对单个文件的修改。安装 Git，从 Git 工作树启动 MiniBot，并在 MiniBot YAML 中启用此功能。

```yaml
file_checkpoints: true
```

MiniBot 记录内置 `write_file` 和 `edit_file` 工具造成的更改。每个检查点把更改前后的字节和权限位存入 `<app_home>/file-checkpoints/` 下的私有 Git 仓库。使用同一工作区和应用主目录的会话共享此仓库，其历史包含文件内容副本，也可能包含其中的秘密信息。

在 REPL 中列出检查点、预览记录的差异，再选择要恢复的检查点。

```text
/checkpoint list
/checkpoint diff ID
/checkpoint rollback ID
```

按提示确认回滚。如果文件仍与记录的修订一致，MiniBot 会恢复原字节和权限位。如果该检查点创建了文件，回滚会删除文件并保留父目录。同一文件有多次编辑时，先回滚最新一次。工作区的 Git 索引、分支和无关文件保持现状。

Python SDK 使用 `Config(file_checkpoints=True)` 启用功能。对得到的 `Minibot` 实例，可等待 `list_file_checkpoints()`、`diff_file_checkpoint(id)` 或 `rollback_file_checkpoint(id)`。恢复成功返回 `True`，已恢复过的检查点返回 `False`。检查点缺失、发生冲突或回滚被中断时抛出 `FileCheckpointError`。

每份快照支持最多 16 MiB 文件数据。MiniBot 记录工作区内解析后的正规文件路径，且文件只能有一个硬链接。内容未变的写入，以及 Bash、MCP 或自定义工具造成的修改，都不会生成检查点。目标被替换为符号链接，或字节和权限与记录不符时，回滚会被拒绝。恢复时请暂停其他写入同一文件的程序。MiniBot 串行处理自身的检查点操作，其他程序仍可能与最后的文件系统更新发生竞争。

进程突然退出时，已记录的写入可能还未落到工作区。如果更改后的状态不存在，常规回滚检查会拒绝操作。如果在记录回滚开始与完成之间中断，状态显示为 `rollback_incomplete`。继续修改前请检查当前文件和记录的差异。MiniBot 会阻止自动重放此检查点。
