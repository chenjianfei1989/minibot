# 第 02 讲 模型请求组装

看到实际提交给模型的参数，并能解释兼容层。

## 源码导读

从 Agent._budgeted_message() 找到 prepare_model_request()，区分请求消息、工具定义与输出额度。再读 LLMClient 的请求参数组装和异步发送，比较同步兼容、非流式和流式入口。模型响应中的文本、推理、用量和工具请求各有提取路径。

[core/client.py](../../src/minibot/core/client.py) · [core/model_context.py](../../src/minibot/core/model_context.py) · [agent.py](../../src/minibot/agent.py)

## 配置核对

核对 llm.base_url、api_key、model、max_tokens、max_context_tokens 和 reasoning_effort。区分环境变量占位符、模型配置和单次请求参数。

## 使用与验证

阅读假客户端时记录捕获的请求字典，标出 model、messages、tools、stream 分别由哪一层写入。

在仓库根目录运行本讲的定向测试。测试可在未配置真实模型凭证的环境中执行。

```powershell
uv run --with pytest --with pytest-asyncio python -m pytest -q tests/test_llm_client_async.py::test_create_message_async_uses_async_client
```

## 阅读验收

能画出一份请求参数从配置和会话进入模型 API 的路径，并指出失败重试发生在哪一层。
