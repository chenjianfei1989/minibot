# 第 08 讲 流式输出与事件路由

理解模型分片如何变成客户端消费的事件。

## 同一段回答怎样逐步到达界面

用 `stream()` 发出「你好」，调用方得到的是可异步迭代的事件流。SDK 在 `_stream_events()` 里启动后台生成任务，前台从队列中逐个取事件。Agent 读取模型流，把正文、推理和工具调用的片段分别处理。正文可以立刻派发，工具参数则要等完整拼好，才能进入后续分发。

追踪 `Agent._emit()` 时，先看事件是否进入追踪，再找事件接收器。`RouterEventSink` 可以把同一事件交给持久化回调，再转发给当前订阅队列。这样，界面显示增量和 SDK 持久化部分消息分别有自己的消费路径。

## 读懂事件的边界

| 事件 | 阅读时关注 |
| --- | --- |
| `assistant_delta` | 这次模型响应刚产生的正文片段 |
| `assistant_end` | 本次助手响应结束，之后仍可能进入工具执行 |
| `tool_call` 与 `tool_result` | 工具执行前后的结构化通知 |

消费者提前关闭可能只解除订阅。若要主动停止生成，需要按 SDK 入口的约定调用 `cancel()`。当流式请求失败时，Agent 还可能标记流式降级并改走非流式请求。定位「页面停了但后台仍在工作」时，分别检查队列、生产者任务和中断状态。

**思考与答案**　为什么不能看到第一段工具参数就开始执行？分片可能只包含半个 JSON 对象。必须先按调用索引合并，才能验证并执行。

## 使用与验证

运行分片测试，在假模型响应中找出分段出现的参数和最终执行时收到的完整对象。

```python
import asyncio
from minibot import Minibot


async def main():
    bot = Minibot()
    async for event in bot.stream("你好"):
        if event["type"] == "assistant_delta":
            print(event.get("delta_text", ""), end="", flush=True)


asyncio.run(main())
```
