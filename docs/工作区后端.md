# 配置工作区后端

设置 `workspace.backend: docker`，让 Bash 与文件读取、写入、编辑和目录列表在同一个 Docker 工作区执行。CLI 和 WebUI 在 `$MINIBOT_HOME/config/default.yaml` 中配置。SDK 可以传入 `WorkspaceConfig`。

## 选择工作区目录

从工作区外的安装目录和 Python 环境运行 MiniBot。将 `MINIBOT_HOME`、会话和追踪也放到工作区之外，并使用专用工作区目录。Bash 命令可访问放在工作区内的所有内容，包括凭证、硬链接文件和套接字文件。

使用可信的本地 Docker 守护进程和镜像。Docker 引擎必须支持挂载选项 `bind-recursive=disabled`，以排除嵌套的宿主机挂载。启动 MiniBot 前预加载默认镜像。

```sh
docker pull python:3.12-slim
```

自定义镜像须提供 `/bin/sh` 和含标准库的 Python 3。MiniBot 拒绝声明了卷的镜像。如果运行重启后需要使用同一镜像，将 `image` 设为本地可用的不可变镜像 ID。

## 启用 Docker 执行

以下是 Docker 执行的默认配置。修改后重启 MiniBot。`workspace.timeout` 接受正数，单位为秒。默认的 `null` 表示使用 `tools.timeout`。

```yaml
workspace:
  backend: docker
  image: python:3.12-slim
  network: none
  memory_mb: 512
  cpus: 1.0
  pids_limit: 128
  timeout: null
```

设置 `network: bridge` 允许操作访问 Docker 桥接网络。仅在命令需要与容器外通信时启用。MiniBot 不会转发宿主机环境变量或 Docker CLI 代理设置，选定镜像定义的变量仍然可用。

在 SDK 中，创建 Bot 时提供工作区和运行时路径。

```python
from pathlib import Path

from minibot import Minibot
from minibot.config import Config, WorkspaceConfig

runtime = Path("/path/to/minibot-runtime")
bot = Minibot(
    config=Config(
        workdir=Path("/path/to/project"),
        app_home=runtime,
        workspace=WorkspaceConfig(backend="docker"),
    ),
    sessions_dir=runtime / "sessions",
)
```

每次操作都启动一个新容器，其起始目录为 `/workspace`。该目录使用可读写的绑定挂载，文件能跨操作保留。每个容器的根文件系统只读，`/tmp` 提供 64 MiB 临时文件系统，禁用 Linux capabilities 和权限提升。POSIX 上，容器进程使用宿主用户的 UID 和 GID。Shell 和文件操作共用超时、取消和清理逻辑。Docker 守护进程阻塞时，清理可能超出操作的超时限制。无法确认清理时，MiniBot 会在错误或取消诊断中报告容器名。若 Docker 强制终止文件写入或编辑，工作区可能留下 `.minibot-write-*` 暂存文件。目标文件在提交时原子替换。

文件工具使用工作区相对路径。例如，Bash 执行 `printf hello > results.txt` 后，可用 `read_file` 读取 `results.txt`。`list_dir(".")` 返回工作区根目录的直接条目。文件工具拒绝绝对路径、父级遍历、符号链接和非常规文件目标。写入和编辑的文件内容上限为 16 MiB，每个目录最多列出 1,000 项。

## 宿主机能力与运行恢复

Docker 工作区模式拒绝活跃 Hooks、已配置的 MCP 连接和自定义 Python 工具注册。WebUI 会在加载之前拒绝已配置的插件和挂载的子 Agent Bot。此模式下 Skills、记忆、Team 和 Task 不可用。启动 MiniBot 前，从可信的应用主目录配置中关闭不兼容项。空的 Hooks 和 MCP 配置可以沿用默认启用设置。

工具审批和运行预算仍适用。Docker 无法完成的文件操作返回错误。所有工作区文件和 Shell 操作都在 Docker 内执行。

Docker 工作区模式下请停用 Git 文件检查点。Git 文件检查点和回滚在可信本地模式下可用。工作区快照留待后端未来支持。持久化执行记录工作区 ID，恢复时要求使用相同的目录和策略。Agent 运行期间保留原目录。在原路径换一个目录也会改变 ID。产物关联该工作区 ID，从应用运行时目录读取。[启用持久化执行](持久化执行.md) · [配置上下文卸载](上下文卸载.md)

## 可信本地模式

默认的 `workspace.backend: local` 让文件工具以宿主用户身份运行。按默认 Bash 策略，Shell 命令拥有宿主机访问权限。可以设 `tools.bash.backend: docker` 仅隔离 Bash，或在任一工作区模式下用 `disabled` 停用 Bash。选择 `workspace.backend: docker` 时，工作区策略为 Bash 和文件操作提供镜像与限制。[配置仅 Bash 隔离](Bash隔离.md)

## 运行 Docker 验证

本地 Docker 守护进程可使用默认镜像后，运行显式启用的工作区集成测试。

```sh
MINIBOT_TEST_DOCKER=1 uv run --with pytest --with pytest-asyncio pytest tests/test_workspace_docker_integration.py -q
```
