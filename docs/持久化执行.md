# 持久化执行

在 `$MINIBOT_HOME/config/default.yaml` 中或构造 SDK 时启用持久化执行。默认值是 `false`。

```yaml
durable_execution: true
```

```python
from minibot import Minibot

bot = Minibot(workdir=".", session_id="your-session", durable_execution=True)
result = await bot.chat("写一份摘要，然后检查内容。")
```

重启后，打开相同的应用主目录、工作区配置和会话。可以通过 `list_sessions()` 查询会话 ID。

```python
bot = Minibot(workdir=".", session_id="your-session", durable_execution=True)
for run in bot.list_runs(incomplete_only=True):
    print(run.run_id, run.status, run.segment)
    for step in bot.list_run_steps(run.run_id):
        print(step.ordinal, step.name, step.status, step.artifact_id)
```

调用 `await bot.resume_run(run_id)` 获取完成的响应，或迭代 `bot.resume_run_stream(run_id)` 接收实时事件和审批请求。`data.code = "durable_run_started"` 的 `system` 事件包含持久化运行 ID 和片段编号。现有流式客户端可以继续使用原有的模型、工具和审批事件。

每个会话同一时间只能有一个未完成的运行。开始新一轮前，应继续或放弃原运行。已完成的运行可通过 `resume_run` 重新读取。MiniBot 返回已保存的结果，保留当前会话历史。WebUI 也会等到未完成的运行处理完毕，再允许删除会话，或删除、重新生成其中的一轮。

## 暂停与恢复

`bot.pause_run(run_id)` 会为活跃运行记录暂停请求。MiniBot 在到达下一次模型或工具调用的边界时，或在等待用户回复、审批期间响应请求。正在执行的工具可以完成并记录结果。每次显式恢复都会开始新的运行预算片段。仍需执行的调用遵循当前工具权限。

重启后，读取运行和步骤状态。`interrupted` 通常可以恢复。`waiting` 状态下等待用户回答的问题可在恢复后的事件流中再次展示。等待审批期间发生中断，旧审批 ID 将失效。恢复时仍需审批的调用会发出新请求。

`recovery_required` 表示进程进入了可能产生副作用的步骤，却在记录结果前退出。检查目标系统，确认实际发生了什么。用 `bot.resolve_run_step(run_id, step_id, output, is_error=False)` 记录已经核实的结果，再恢复运行。无法确认安全结果时，可用 `bot.abandon_run(run_id)` 结束运行。实际已经发生的副作用会保留。SDK 将每项操作限定在选定的工作区和会话中。

内置读取工具或提问操作被中断时，如果调用没有前置或后置工具钩子且恢复时仍满足条件，MiniBot 可以重试。Bash、文件写入和编辑、自定义工具或 MCP 工具丢失执行结果时，需要操作人员介入。已提交的调用结果按顺序复用，包括卸载后的产物引用。已经写入运行日志的 `Task` 会从原步骤继续，沿用已关联的子运行。

## CLI 和 WebUI

在 CLI 中使用 `/session load` 选择原会话。通过 `/run list` 查找未完成的运行，再使用 `/run resume ID` 或 `/run abandon ID`。对于结果不明的工具步骤，使用 SDK 记录核实后的结果。

服务端启用持久化执行后，WebUI 的现有提问交互会在用户回答后恢复原运行，继续执行该批工具。通用的运行发现、暂停和人工恢复通过 SDK 完成。文件检查点继续独立处理工作区编辑。

## 持久化内容

MiniBot 在应用主目录下的 `runs/journal.sqlite3` 保存带版本的运行时检查点和有序工具日志。检查点包含消息和当前模型请求的工具批次。即使服务商重复使用工具调用 ID，每个工具步骤也有独立 ID。如果进程在记录模型响应前退出，可以从最后提交的检查点重复请求模型。MiniBot 为活跃运行及其会话持有操作系统锁，在接入前检查解析后的工作区、执行配置和会话存储。会话历史仍采用 JSONL。启用追踪时，每个执行片段单独记录。

日志保存提示词、工具参数和结果预览。请像保护会话历史一样保护应用主目录，共享同一会话的进程应沿用同一应用主目录。持久化子 Agent 使用同一日志库，具有独立的运行和会话占用记录。团队状态沿用原有存储和生命周期。[持久化沙箱子 Agent](持久化沙箱子Agent.md)
