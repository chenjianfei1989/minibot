# 运行预算

MiniBot 对每个执行片段施加累计预算。主 Agent 与内置 `Task` 子 Agent 共用预算。独立的团队成员运行，以及从持久化问题恢复的每次执行，都会开始新片段。

在 MiniBot 应用主目录下的全局 `config/default.yaml` 中设置限制。已有文件若缺少此项，将采用以下默认值。数值必须为正。`max_wall_time` 以秒为单位，允许小数。

```yaml
runtime_budget:
  max_llm_calls: 30
  max_tool_calls: 100
  max_wall_time: 600
  max_input_tokens: 200000
  max_output_tokens: 50000
```

Python SDK 可通过 `Config` 传入相同策略。

```python
from minibot import Minibot
from minibot.config import Config, RuntimeBudgetConfig

bot = Minibot(config=Config(runtime_budget=RuntimeBudgetConfig(max_llm_calls=12)))
```

模型请求在发出时计作一次尝试。流式失败后改用非流式请求，或发起一次压缩，都会单独计数。模型客户端或 HTTP 传输内部的重试计入同一次尝试。最终回复已准备好且剩余预算不足以启动可选压缩时，MiniBot 会保留该回复。工具尝试在执行前计数，包括策略拒绝或参数解析失败的调用。

token 限制在发送前根据估算检查，服务商返回提示词和生成计数时使用报告值。请求的生成上限受剩余输出额度约束。没有报告值时，会估算可见文本、推理及工具参数，其中包括流式回退前已收到的部分输出。输入估算可与服务商分词结果不同。实际用量超限时，在下一次工具或模型请求前停止运行。

到期会取消仍在等待的模型请求或工具执行，并允许协作式清理完成。Agent 等待用户现场回复时暂停计时。同步阻塞代码、自定义工具分离出去的任务，以及取消后服务商仍继续的工作，可能超过期限。

停止时会发出 `system` 事件，`data.code` 为 `budget_exceeded`，`data.limit` 指明耗尽的限制。直接调用 `Agent.run_loop` 会抛出 `RuntimeBudgetExceeded`，SDK 聊天会把原因放进助手错误消息。启用[追踪](执行追踪.md)时，结尾记录会包含相同的状态和限制。当前批次已返回的工具结果保留在历史中，被跳过的调用得到拒绝结果。
