# 第 10 讲 会话历史与消息结构

理解同一个 Bot 怎样接续历史和隔离多个会话。

## 一次聊天的记录如何跨进程保留

先在两个会话分别输入不同的话，再加载其中一个会话。接续成功依赖正确的 `session_id` 和会话存储目录。SDK 的 `set_session()` 负责切换 Agent 使用的 ID 再加载历史。`SessionManager` 将持久化交给 `SessionStore`，后者根据日期与 ID 定位 JSONL 文件，并逐条读写消息。重启会重建内存对象，历史依然可以从这个文件加载。

## 从一组消息认识关联关系

找一次有工具调用的聊天，按顺序写下用户消息、助手工具请求、工具结果和最终助手回复。它们各有 `message_id`。助手结果中的 `parent_user_message_id` 把输出关联到用户轮次，工具结果的 `tool_call_id` 绑定模型给出的调用。在重新发送给模型之前，`session/messages.py` 中的规范化逻辑还会整理持久化工具调用的格式。

会话历史之外还有小型运行时状态，用于记录例如流式生成或待回答问题。开启持久化执行后，运行日志也有独立用途。看看 `SessionStore` 如何分别读消息和运行时状态，就能避免把恢复线索等同于聊天正文。

**思考与答案**　只保留一轮最终助手正文，还能精确还原工具往返吗？不能。工具请求、结果以及关联 ID 要一并保留。

