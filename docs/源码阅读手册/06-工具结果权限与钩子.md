# 第 06 讲 工具结果权限与钩子

理解一次调用在哪些位置获准、被拒绝或执行失败。

## 审批是执行前的决定，钩子是执行流程中的扩展点

设想工具准备写某个文件。将工具请求交给权限层后，策略根据工具名和默认规则决定允许、拒绝或询问。需要询问时，WebUI 或 SDK 可以接收审批事件，按审批 ID 提交决定。审批通过后仍会进入前置钩子。这样可以清楚区分「用户同意了调用」与「工具确实成功执行了」。

回到 `execute_with_hooks()`，从前置钩子、工具本体到后置钩子画出顺序。再打开 `ToolOutcome`，对照状态和 `is_error` 的计算。如果工具完成但后置钩子报错，系统可以保留实际执行状态，同时暴露钩子诊断。调试时不要只看工具返回的文本，要同时核对结构化结果。

## 观察一条被拒绝的调用

手工审批练习使用临时工作区和无副作用的只读工具。先让审批回调拒绝，再批准同一请求，比较工具本体的执行次数。配置里的 `mode` 决定是否进入审批流程，`default` 与 `rules` 决定规则匹配，`timeout` 限制等待。模型审核另有允许路径和工具类型约束。

**思考与答案**　审批通过后如果权限目标被替换，应把它当作原文件继续执行吗？执行路径会重新检查批准时记录的目标与当前解析目标是否一致。读 `ApprovedCall.still_targets()` 可以看到这一点。
