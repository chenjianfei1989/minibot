# 第 13 讲 预算中断与等待用户

理解 Agent 怎样被限制、取消或暂停等待回答。

## 模型、工具与前端各在哪儿停下来

一次 Agent 执行有独立的预算片段。`RuntimeBudget` 同时处理模型请求数、工具请求数、输入和输出 token，以及运行时间。读 `start_model()` 和 `finish_model()`，就能区分请求发出前的额度校验与响应后实际计量。工具计数也有自己的入口。持久化恢复可以开始新的执行片段，所以不能仅凭一次模型调用判断整轮还剩多少预算。

| 停顿原因 | 主要观察对象 |
| --- | --- |
| 预算耗尽 | 哪个限制被触发，Agent 如何发出状态并退出 |
| 调用方取消 | SDK 的中断队列、挂起交互和 Agent 的清理路径 |
| Agent 等待用户回答 | 问题 ID、选项与等待中的异步结果，以及提交答案入口 |

## 跟一次提问工具

模型选中提问工具后，前端收到问题事件。SDK 可以保持活跃流等待 `submit_user_answer()`，也能按配置在提问处暂停，稍后从保存状态恢复。分析等待时长时，要打开 `RuntimeBudget.pause()` 看哪些时间被剔除。取消与预算异常还可能发生在等待模型、执行工具或收尾阶段，报告状态时应指明发生点。

**思考与答案**　用户在选择选项界面停了很久，一定会耗尽当前执行的有效时间预算吗？等待用户时有独立的暂停逻辑。应结合具体等待分支和预算上下文判断。

## 使用与验证

用假模型连续返回工具请求，跟踪模型调用额度耗尽的分支。另在问答测试里观察问题 ID 和答案的匹配。

在仓库根目录运行本讲的定向测试。测试可在未配置真实模型凭证的环境中执行。

```powershell
uv run --with pytest --with pytest-asyncio python -m pytest -q tests/test_runtime_budget.py::test_model_call_cap_ends_run_and_resets_for_next_run
```
