# 第 14 讲 持久化执行与恢复

把 run ID、运行状态与工具步骤对应到 SQLite 日志。

## 源码导读

从 _run_durable_once() 和 resume_run_id 进入 RunStore，逐一读 runs、checkpoints、steps。对照完成结果、等待状态、检查点恢复以及结果不明步骤的处理，观察恢复后消息怎样同步回会话。

[sdk/minibot.py](../../src/minibot/sdk/minibot.py) · [agent.py](../../src/minibot/agent.py) · [core/run_store.py](../../src/minibot/core/run_store.py) · [session/store.py](../../src/minibot/session/store.py)

父运行与持久化子运行共用日志库。继续读 `child_runs`、`child_containers` 和 `child_deliveries`，分别追踪父子关系、Docker 容器记录和文件交付凭据。父运行进入 `waiting_child` 后，可用 `list_child_runs()` 查看子运行。

## 配置核对

durable_execution 启用运行日志。恢复需要同一应用主目录、工作区、会话和兼容的执行策略。当前工具权限仍会影响剩余调用。

[相关配置与使用指南](../持久化执行.md)

## 使用与验证

使用 list_runs()、list_run_steps() 和 resume_run() 跟踪一次暂停后的恢复。先用测试中的临时会话验证。

在仓库根目录运行本讲的定向测试。测试可在未配置真实模型凭证的环境中执行。

```powershell
uv run --with pytest --with pytest-asyncio python -m pytest -q tests/test_durable_execution.py::test_pause_at_boundary_and_completed_attach_preserves_newer_history
```

## 阅读验收

能区分恢复一个未完成运行和读回一个已完成运行，并解释哪些有副作用的步骤需要人工核实。
