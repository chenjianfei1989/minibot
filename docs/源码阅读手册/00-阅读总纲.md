# MiniBot 源码阅读手册

学完后，能够从源码解释 MiniBot 的执行行为，知道每项配置如何生效，并能用 CLI、WebUI、Python SDK 和外部平台完成对应操作。按 24 讲的顺序阅读，每讲用现有源码、配置和可验证的使用场景互相对照。

## 学习目标与验收

| 目标 | 完成标准 |
| --- | --- |
| 读懂全部源码 | 能从用户入口追到模型请求、工具执行和结果返回，读清正常、失败、中断与恢复路径。按仓库目录逐文件核对，说明每个模块的职责、关键数据与调用方。 |
| 读懂全部配置 | 能逐项解释配置含义、类型、默认值、生效条件、来源优先级和读取位置。能从观察到的行为反查配置，也能从配置定位最终使用它的代码。 |
| 读懂使用方式 | 能从源码启动项目，用 CLI、WebUI 和 SDK 验证普通对话、工具调用、流式输出和会话恢复，并说明可选功能的启用条件及使用入口。 |

## 配置覆盖清单

- 逐项阅读 [默认配置](../../config/default.yaml)、[Hooks 配置](../../config/hooks.yaml)、[MCP 配置](../../config/mcp_servers.yaml)和[环境变量示例](../../.env.example)。
- 用[配置模型](../../src/minibot/config/schema.py)、[加载代码](../../src/minibot/config/settings.py)和[写回代码](../../src/minibot/config/writer.py)补齐示例中省略的字段，核对默认值、覆盖顺序和配置修改何时生效。
- 跟踪 CLI、WebUI 与 SDK 各自可传入或修改的设置。需要区分配置文件、环境变量、构造参数和运行时修改时，按对应入口分别验证。
- 第 24 讲补齐 [Python 项目配置](../../pyproject.toml)、[前端脚本和依赖](../../webui/package.json)、[Vite 配置](../../webui/vite.config.ts)与 CI、发布配置。

记录每个配置项时，至少写明 **完整键名、可选值或类型、默认值、读取位置、生效范围、验证场景**。没有统一优先级的设置按各自的加载路径记录。

## 每讲怎么读

1. **从使用场景出发。** 记录入口命令、SDK 方法或 WebUI 操作，以及预期输出。
2. **顺调用链读实现。** 记下文件与函数名、参数、关键状态和返回值，覆盖相关的异常分支。
3. **核对生效配置。** 找出影响该链路的字段，沿着加载、校验和使用位置读一遍。
4. **用测试验证。** 优先使用能控制模型响应的现有测试。需要真实模型、Docker 或外部平台时，记录前置条件和实际验证结果。
5. **登记阅读覆盖。** 标记已读文件、已核对配置和已验证场景。各阶段结束时用 `git ls-files` 对照目录，补读入口链路未经过的模块、辅助函数、测试和脚本。
