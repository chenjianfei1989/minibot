# 执行追踪

MiniBot 可以将轻量的执行元数据写入 UTF-8 JSONL 文件。默认关闭记录。

## 配置

在全局 `config/default.yaml` 中设置顶级键 `trace_dir`，即可启用记录。配置加载时，相对路径按应用主目录解析，服务端 Bot 继承解析后的路径。绝对路径直接指定目标。

```yaml
trace_dir: traces
```

SDK 和直接调用的 `Agent` 入口均可通过 `Config` 使用同一设置。

```python
from pathlib import Path
from minibot import Minibot
from minibot.config import Config

bot = Minibot(config=Config(trace_dir=Path("traces")))
result = await bot.chat("介绍这个项目")
```

设置 `trace_dir: null` 可关闭记录。追踪文件没有自动保留期限或轮转。

## 记录

每个执行片段独占一个新建的 `<run_id>.jsonl`。不同会话和进程使用各自的 UUID 与文件。执行继续前会刷新当前行，无后台缓冲区或共享追加文件。

每条记录包含 `version`、`event`、`run_id`、`session_id`、`sequence` 和 `elapsed_ms`。版本为 `1`，序号在运行中递增。经过时间和持续时间使用单调时钟，单位为毫秒。`run_start.started_at` 是 UTC 实时时钟时间戳。

| 事件 | 额外字段 |
| --- | --- |
| `run_start` | `scope`、`parent_run_id`、`started_at` |
| `tool_start` | `invocation_id`、`tool_call_id`、`tool_name` |
| `tool_end` | 同一组调用字段、`status`、`is_error`、`duration_ms`，可选 `exit_code` 和 `hook_phase` |
| `subagent_start` | `child_run_id`、`parent_invocation_id`、`agent_type` |
| `subagent_model_start` | 子运行 ID、父调用 ID 和 `invocation_id` |
| `subagent_model_end` | 同一组模型调用字段、`status`、`duration_ms`，可选 `usage` |
| `subagent_tool_start` | 子运行 ID、父调用 ID、`invocation_id`、`tool_call_id`、`tool_name` |
| `subagent_tool_end` | 同一组子工具字段、`status`、`is_error`、`duration_ms`，可选 `exit_code` 和 `hook_phase` |
| `subagent_end` | 子运行 ID、父调用 ID、`status`、`duration_ms`，可选 `budget_limit` |
| `artifact_created`、`artifact_search`、`artifact_read` | 调用 ID、产物 ID、来源运行 ID 和工具名、字节大小、内容类型，以及可选的子运行 ID 和父调用 ID |
| `tool_approval` | `approval_id`、`tool_name`、`approved`、`source` |
| `run_waiting` | 无 |
| `run_resumed` | 无 |
| `run_end` | `status`、`duration_ms`，可选 `budget_limit` |

即使服务商重复工具调用 ID，内部调用 UUID 也能配对每次工具开始和结束。工具状态保留 `ToolOutcome` 的值。取消时记录 `interrupted` 并继续抛出原中断异常。后置钩子失败时，工具状态可以仍为 `success`，同时设置 `is_error`，并将 `hook_phase` 标为 `post`。

工具计时始于发送 `tool_call` 之前，终于发送 `tool_result` 之前，包含这段时间内的前置钩子、工具执行、后置钩子、所属清理工作、终端渲染和事件投递延迟。JSON 参数解析发生在计时前。提问工具成功执行后才开始等用户，因此用户回复时间不计入工具耗时。

## 生命周期

运行结束状态有 `completed`、`failed`、`interrupted`、`waiting_for_user`、`budget_exceeded` 和 `context_window_exceeded`。[上下文窗口超限](模型请求上下文限制.md)表示请求在发送前无法放入窗口。预算停止时，`budget_limit` 记录触发的配置项。[运行预算](运行预算.md)

`completed` 表示执行循环已经返回。工具失败也可能出现在已完成的运行中，用户任务是否成功需要另行判断。`assistant_end` 之后可能继续执行工具或请求模型，运行仍可继续。

现场提问发出 `run_waiting`，回答在同一次运行中发出 `run_resumed`。持久化暂停后的结束状态为 `waiting_for_user`。运行时旁车文件保存 `trace_run_id`，服务端的回答流路由会将其传为恢复片段的 `parent_run_id`，即使 Bot 缓存已被清除或进程已重启也一样。旧旁车文件没有此字段时，片段不关联。这些关联本身不提供检查点重放或副作用去重。SDK 的 `resume_pending_question_stream` 继续运行已准备好的历史。在服务端路由之外，调用方仍需自行持久化答案。

SDK 流式运行复用生产者的所有权 UUID。分离或关闭异步读取器后，生产者和记录器继续运行。SDK 取消和同步迭代器关闭仍执行原有生产者清理。结束记录出现在所属工具完成清理之后。运行结束反映 SDK 后续保存消息以前的 Agent 执行状态，消息是否持久化需要另行确认。

## 跟踪 Task 子 Agent

找到工具名为 `Task` 的父级 `tool_start`。它的 `invocation_id` 与子记录的 `parent_invocation_id` 对应。这些记录共用父运行的 JSONL 文件。每次子执行有自己的 `child_run_id`。即使服务商复用调用 ID，每次子模型尝试和工具调用也有单独的 `invocation_id`。

`subagent_end` 报告 `completed`、`failed`、`interrupted`、`budget_exceeded` 或 `context_window_exceeded`。预算停止通过 `budget_limit` 给出限制。服务商返回响应时计作模型尝试完成，子 Agent 后续处理响应时仍可能失败。服务商提供 token 统计时，模型记录也包含对应值。

## 记录范围和输出策略

`scope` 为 `agent_tools`。记录覆盖所属 Agent 循环内的工具及内置模型驱动 `Task` 路径中的子操作。团队成员、自定义处理器及挂载 Bot 的处理器不生成这种格式的子记录。

单独调用且启用了追踪的 Agent 会创建自己的运行。直接调用 `Agent.run_loop`、SDK 聊天、流式接口和同步包装均支持记录。

[工具审批](工具权限与审批.md)决定记录到拥有该决定的 Agent 运行中，包括委派 Agent 请求的决定。审批预览和审核提示词不记录。

记录采用字段允许列表，省略提示词、参数、工具输出、助手文本、推理、通用系统载荷、异常消息和钩子诊断字符串。会话 ID、工具名和服务商调用 ID 仍作为元数据存入文件。避免在这些标识中放入凭证。

打开、写入、刷新或关闭失败时，`minibot.traces` Python 日志器会发出固定警告，并禁用受影响的记录器。生成仍继续，追踪保留取消行为且不触发重试。目标不可用、进程崩溃或被强制终止时，追踪可能缺失或不完整。读取方应看到最后的 `run_end` 后才把文件视为完整。刷新缓冲不保证文件在系统崩溃后仍然持久。

契约测试会读取生成的文件，覆盖失败、重复 ID、并发会话、暂停和恢复、读取方分离、UTF-8、写入失败和真实 Bash 进程清理。

```bash
uv run --with pytest --with pytest-asyncio pytest tests/test_run_traces.py tests/test_server_webui_bots.py -q
```

## 运行任务回归检查

从仓库根目录运行固定任务，测试使用脚本化模型和临时工作区。

```bash
uv run --with pytest --with pytest-asyncio pytest -v tests/test_task_regression.py
```

测试覆盖创建和编辑文件、前置工具钩子拒绝、工具失败后回退、执行工具时取消，以及通过新服务实例恢复已持久化的问题。这些场景无需模型凭证、Docker 守护进程或活跃的 Web 服务。

每个任务都会检查追踪中的步骤和结束状态、操作日志及最终文件。如果场景预期工具出错并成功回退，任务仍可通过。追踪不可用或内容不符时，任务会失败，输出诊断并返回非零退出码。相同命令还会运行探针，故意损坏已采集的追踪或操作结果，验证能够发现相应问题。现有 CI 的 pytest 步骤会自动发现这组用例。
