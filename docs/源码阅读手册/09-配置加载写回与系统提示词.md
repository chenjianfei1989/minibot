# 第 09 讲 配置加载写回与系统提示词

从某个设置的值反查它从哪来、最后在哪使用。

## 源码导读

从 load_config() 追踪应用主目录、配置模板、环境变量占位符及默认值，再看配置对象的字段校验。对照 Agent.__init__() 消费配置并调用 _build_system_prompt() 的过程。用 writer.py 跟踪交互修改写回的目标。

[config/settings.py](../../src/minibot/config/settings.py) · [config/schema.py](../../src/minibot/config/schema.py) · [config/writer.py](../../src/minibot/config/writer.py) · [config/workspace.py](../../src/minibot/config/workspace.py) · [agent.py](../../src/minibot/agent.py)

## 配置核对

对照 .env.example、config/default.yaml、config/hooks.yaml 和 config/mcp_servers.yaml。先验证进程环境与全局 .env 的关系，再逐项记录配置的来源、默认值、生效和写回范围。

## 使用与验证

在单独的临时应用主目录准备测试配置，把同一个模型变量分别放在 .env 和进程环境中，观察最后加载的值。

在仓库根目录运行本讲的定向测试。测试可在未配置真实模型凭证的环境中执行。

```powershell
uv run --with pytest --with pytest-asyncio python -m pytest -q tests/test_config_loading.py::test_load_config_env_precedence_process_over_global
```

## 阅读验收

能为一个字段写出『配置来源 → 解析与校验 → 消费方 → 是否需重新加载』的路径。
