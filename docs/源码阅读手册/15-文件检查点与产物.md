# 第 15 讲 文件检查点与产物

分辨文件回滚、工具输出保存和运行记录三种用途。

## 文件变更与工具输出各自有记录

Agent 把某个本地文件改错了，想撤回这个更改，可以查文件检查点。Agent 读出一份大日志，想在原始工具结果中继续搜索，可以查本地产物。两者都记录了数据，但前者针对可回滚的文件更改，后者提供按 ID 访问输出的方式。持久化运行则维护步骤状态，帮助判断一次执行能否继续。

## 为什么回滚前要比对当前文件

打开 `GitFileCheckpoints`，看文件修改前后的字节和权限模式怎样进入私有 Git 对象存储。回滚只在当前文件与记录中的修改后版本匹配时执行，以保护之后发生的变更。在临时 Git 工作树中可以先生成一个检查点，再在同一文件上制造额外改动，阅读对应拒绝路径或运行其测试。

产物检索的入口则从 `ArtifactStore` 开始。结合第 11 章理解为什么大结果先保存在本地，模型使用读取或搜索工具拿所需片段。产物 ID 和会话作用域共同限定可见范围。

**思考与答案**　一个工具结果带产物引用，是否代表对应文件可以回滚？产物引用只证明文本结果保留供检索，能否回滚要看具体文件操作有没有创建检查点以及目标当前状态。

## 配置核对

file_checkpoints 控制文件快照，依赖受支持的 Git 工作树和工作区模式。产物的内容大小与卸载阈值由 context_offloading 控制。

## 使用与验证

在临时 Git 工作树用 /checkpoint list、diff 和 rollback 查看写入产生的快照。没有相应运行环境时，先读禁用行为的测试。

在仓库根目录运行本讲的定向测试。测试可在未配置真实模型凭证的环境中执行。

```powershell
uv run --with pytest --with pytest-asyncio python -m pytest -q tests/test_file_checkpoints.py::test_disabled_checkpoints_preserve_normal_non_git_writes
```
