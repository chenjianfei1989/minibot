# 第 05 讲 参数解析分发与回填

跟踪一次模型发出的工具调用直到下一次模型请求。

## 从一个工具名字找到真正的函数

假设模型回应「需要调用 `read_file`，参数为 `{"path":"README.md"}`」。响应还带有调用 ID。Agent 先把响应整理成可分发的调用项，随后 `_dispatch_tool_batch()` 按批处理。输入的参数可能是 JSON 字符串，也可能被额外文本包裹。先从 `parse_tool_arguments()` 看这一层怎样尝试恢复格式，再从注册表看未知名称和无效签名怎样返回诊断。

参数解析成功只表示基本结构可用。实际执行前还要确认工具存在，权限允许，且调用与 Python 签名匹配。对比「JSON 本身坏了」和「JSON 合法但字段不对」的路径，有助于定清哪一层负责报告错误。

## 结果通过 ID 关联

发现某次工具结果时，把它的 `tool_call_id` 与助手工具调用的 ID 配对。一次助手响应可以包含多个请求，如果只按工具名配对，同一个工具被调用两次就会歧义。`role="tool"` 消息负责把结果送回模型。展示用的状态和诊断则通过执行结果、事件或应用的数据模型传递。

做一个小对照：给同一函数准备正确 JSON 和不能恢复的 JSON。跟踪分发的返回值和工具函数是否实际进入。下一章再在这一条路径上叠加审批和 Hooks。

**思考与答案**　模型已经给出正确的工具名，函数仍可能没执行吗？可能。无效参数、权限拒绝、预算耗尽和前置钩子阻止都会在真实调用之前终止该步骤。
