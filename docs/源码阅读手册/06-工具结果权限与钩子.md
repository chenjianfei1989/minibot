# 第 06 讲 工具结果权限与钩子

理解一次调用在哪些位置获准、被拒绝或执行失败。

## 源码导读

从执行包装层追踪权限判断、前置钩子、工具本体和后置钩子。对照 ToolOutcome 的状态、供模型读取的文本和诊断元数据。区分政策拒绝、执行异常和执行成功后钩子报错。

[tools/execution.py](../../src/minibot/tools/execution.py) · [tools/permissions.py](../../src/minibot/tools/permissions.py) · [tools/result.py](../../src/minibot/tools/result.py) · [hooks/manager.py](../../src/minibot/hooks/manager.py) · [hooks/executor.py](../../src/minibot/hooks/executor.py)

## 配置核对

对照 tool_permissions 的 mode、default、rules、auto_review_paths 和 timeout，再查 config/hooks.yaml 的事件、处理器和超时。

[相关配置与使用指南](../工具权限与审批.md)

## 使用与验证

在临时环境使用只读工具验证手动审批，找出 tool_approval_request 和 SDK 的 submit_tool_approval()。也可用假回调对照无需交互的拒绝分支。

在仓库根目录运行本讲的定向测试。测试可在未配置真实模型凭证的环境中执行。

```powershell
uv run --with pytest --with pytest-asyncio python -m pytest -q tests/test_tool_permissions.py::test_chat_without_live_handler_refuses_and_explicit_callback_can_approve
```
