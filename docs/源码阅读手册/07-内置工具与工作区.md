# 第 07 讲 内置工具与工作区

理解工具对文件、命令、待办及产物的操作边界。

## 同一个工具接口，为什么有不同执行后端

做个对照：`TodoWrite` 更新 Agent 的待办管理器，`read_file` 要通过工作区后端读取文件，`bash` 还要管理子进程或容器。它们都能被注册和调用，但资源边界各不相同。阅读时先从工具的参数 Schema 进入 `execute_result()`，再看工具把哪些参数转交给后端，哪些校验由后端完成。

| 模式 | 读写路径 |
| --- | --- |
| 本地工作区 | 文件工具解析到宿主机的工作区路径，命令由 Bash 子配置决定如何运行 |
| 本地工作区配 Docker Bash | 文件工具仍走本地后端，Bash 命令走 Docker |
| 受限 Docker 工作区 | 文件和命令由 Docker 后端处理，容器内文件助手负责实际文件操作 |

## 验证一个路径从哪里读

在临时目录准备一个小 UTF-8 文本。先跟踪本地 `read_file` 如何解析相对路径和读取范围，再顺着 Docker 后端的 `_file_call()` 看它如何把操作交给容器内助手。实际跑 Docker 时应已准备好守护进程和配置中的镜像。单独看 Bash 配置时，要区分 `tools.bash.backend` 与整个工作区的 `workspace.backend`。

**思考与答案**　容器中给工具传入的文件名和宿主机上的绝对路径能直接互换吗？后端分别处理两类路径，在受限 Docker 模式中要使用规范化的工作区相对路径。
