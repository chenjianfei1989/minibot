# 第 10 讲 会话历史与消息结构

理解同一个 Bot 怎样接续历史和隔离多个会话。

## 源码导读

从 set_session()、create_session() 进入 SessionManager，读 JSONL 的追加、读取、覆盖和元数据。对照 message_id、parent_user_message_id、tool_call_id 的用途，再看运行时状态文件和消息历史如何分别读取。

[sdk/minibot.py](../../src/minibot/sdk/minibot.py) · [session/manager.py](../../src/minibot/session/manager.py) · [session/store.py](../../src/minibot/session/store.py) · [session/messages.py](../../src/minibot/session/messages.py) · [server/models.py](../../src/minibot/server/models.py)

## 配置核对

核对 session.enabled、session.sessions_dir 与 SDK 的 session_id 和 sessions_dir 参数，记录路径由哪里解析。

## 使用与验证

终端用 /session new 和 /session list 观察会话切换。用临时目录创建两个会话，分别写入中文消息，对照实际生成的 JSONL。

在仓库根目录运行本讲的定向测试。测试可在未配置真实模型凭证的环境中执行。

```powershell
uv run --with pytest --with pytest-asyncio python -m pytest -q tests/test_session_store.py::test_append_and_load
```

## 阅读验收

能区分会话 ID 与消息 ID，说明为什么续聊依赖原会话以及工具消息如何规范化后再发给模型。
